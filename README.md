# esp32-for-fun-demo

LCDWiki ES3C35P（3.5 英寸 ESP32-S3 显示板，ST77922 + QSPI，320×480）的演示工程。

目标是在**一台可复现的设备上**把板上每个子系统跑通并给出可判读的证据：屏幕、背光、
按键、触摸、RGB 指示灯、音频、电池检测、MicroSD。显示以外的子系统均由 Kconfig
门控，默认关闭；关闭时本工程自身的驱动与场景源码不参与编译，打开时同样接受
编译检查。

工程不依赖厂商示例代码，显示驱动使用 Espressif 官方 `esp_lcd_st77922` 组件，
初始化序列、引脚与时序来自数据手册、原理图与实机测量。

## 一、硬件

| 项 | 值 |
| --- | --- |
| 模组 | ESP32-S3，16 MB Flash，8 MB OPI PSRAM |
| 面板组件 | HMX035CTFT-001 |
| 显示控制器 | ST77922，QSPI 四线 |
| 分辨率 | 320×480，RGB565 |
| 触摸 | ST77922 内置控制器，I2C 地址 0x55，最多 5 点 |
| 音频 | ES8311 编解码（I2C 0x18）+ FM8002E 功放 |
| 指示灯 | XL-5050RGBC-WS2812B |
| 电池检测 | 2:1 分压接入 IO8 |
| 存储 | MicroSD，SDIO 四位 |

### 引脚

| 功能 | 引脚 |
| --- | --- |
| 显示 CS / PCLK / D0 / D1 / D2 / D3 | IO10 / IO12 / IO11 / IO13 / IO14 / IO9 |
| 显示复位 | 接 EN（故配置为不使用复位引脚） |
| 背光 | IO41 |
| BOOT 按键 | IO0 |
| I2C SDA / SCL | IO38 / IO39 |
| 触摸复位 / 中断 | IO48 / IO47 |
| 音频 MCLK / BCLK / WS / DOUT / DIN | IO17 / IO18 / IO21 / IO15 / IO16 |
| 功放使能（低电平有效） | IO1 |
| RGB 数据 | IO40 |
| 电池 ADC | IO8（ADC1 通道 7） |
| MicroSD CLK / CMD / D0 / D1 / D2 / D3 | IO5 / IO4 / IO6 / IO7 / IO2 / IO3 |

IO0 与 IO3 是启动配置（strapping）引脚。IO0 被按下即进入下载模式；
IO3 参与 JTAG 信号源选择，接 MicroSD 时需注意其在上电瞬间的电平。
IO3 在主控复位期间被采样，SD 数据线 DATA3 上的外部电平可能影响采样结果。

## 二、目录结构

```
components/bsp/          板级支持：引脚、总线、子系统驱动
  include/               对外接口，按子系统分文件
  src/                   实现
  Kconfig.projbuild      引脚与时钟、可选子系统开关
components/gfx/          与硬件无关的绘图库（画布、字形、跨度感知）
  test/                  宿主侧单元测试
main/
  app.c                  横带渲染循环、场景调度、按键与串口命令
  scenes.h               场景接口与绘制辅助
  scenes/                各场景
tools/preview/           宿主侧场景渲染与校验（字符图 + 逐像素断言 + 覆盖校验）
configs/                 构建配置变体
scripts/                 构建、烧录、门禁脚本
```

### 依赖方向

```
main  ──►  bsp  ──►  esp_lcd / driver
  └───►  gfx
```

`gfx` 不依赖 `bsp`，因此可以在宿主机上完整测试。`main` 只通过 `bsp` 的公开接口
访问硬件，不直接配置任何 GPIO。

## 三、环境与构建

需要 ESP-IDF v5.5.x。组件依赖由组件管理器自动获取：

| 组件 | 版本 |
| --- | --- |
| espressif/esp_lcd_st77922 | ^2.0.2 |
| espressif/led_strip | ^3 |
| espressif/esp_codec_dev | ^1 |

```bash
# 出厂配置：全部可选子系统关闭
scripts/build.sh

# 全子系统配置：打开全部可选子系统
scripts/build.sh --all

# 混合配置：只开触摸与 MicroSD
scripts/build.sh --mixed
```

三套配置使用独立构建目录（`build/`、`build-all/`、`build-mixed/`）与独立配置文件
（`sdkconfig`、`sdkconfig.all`、`sdkconfig.mixed`），互不干扰。

### 为什么需要三套配置

可选子系统关闭时，本工程自身对应的源码不参与编译。只维护一套配置，这些代码会
长期不被编译器检查，搁置后往往已经不能编译。`--all` 配置保证它们始终处于可用状态。

出厂与全开只覆盖门控的两个角。两个复合条件——I2C 总线（触摸或音频）与 `status`
场景（电池或 MicroSD）——在这两个角上都是"两侧同时成立"，看不出单侧路径的问题。
`--mixed` 让它们各由单侧满足。

代价是三条构建路径都要保持通过，因此提交前的门禁同时构建三者。

### 门控的边界

Kconfig 只能门控本工程自身的源码。`components/bsp/idf_component.yml` 声明的第三方
组件由组件管理器获取，不随开关变化：

- `espressif/led_strip` 与 `espressif/esp_codec_dev` 在两套配置下都会被获取、编译，
  并作为链接输入出现在链接命令中。
- 出厂配置下没有代码引用它们，链接器按 `--gc-sections` 丢弃全部未引用段，
  最终镜像中二者的符号数为 0。

组件管理器不支持按 Kconfig 条件声明依赖。若需要让第三方组件也完全不出现在构建中，
只能把它们移出 `idf_component.yml`，改由 `EXTRA_COMPONENT_DIRS` 手工提供。

同理，`REQUIRES` 也不按 Kconfig 条件裁剪：ESP-IDF 对组件 CMakeLists 做两遍处理，
第一遍在 Kconfig 变量生效前就已注册组件，条件化的依赖会静默丢失。因此
`components/bsp/CMakeLists.txt` 列出的是全部可能用到的组件，未启用子系统的驱动
仍会进入构建图，但不被引用、不进入镜像。

## 四、烧录与运行

```bash
scripts/flash.sh --all          # 构建并烧录全子系统配置
scripts/flash.sh -p /dev/ttyACM0 -b 460800
```

默认端口 `/dev/ttyACM0`，对应 ESP32-S3 的原生 USB-Serial-JTAG 接口。
该接口不会被 esptool 的自动探测列出，必须显式指定端口。

访问串口需要相应权限。把当前用户加入 `uucp` 组后重新登录即可免 sudo。

### 操作

| 方式 | 作用 |
| --- | --- |
| 按 BOOT 键 | 切到下一场景 |
| 串口发 `n` / `p` | 下一场景 / 上一场景 |
| 串口发 `l` | 列出场景 |
| 串口发 `h` | 帮助 |

## 五、场景

| # | 名称 | 内容 | 需要外设 |
| --- | --- | --- | --- |
| 1 | `orient` | 四角方向标记与坐标轴，用于标定屏幕朝向 | 无 |
| 2 | `selftest` | 反色、色块、4 像素对齐、文本 | 无 |
| 3 | `solid` | 纯色循环，用于判断反色与字节序 | 无 |
| 4 | `pattern` | 彩带、16 级灰阶阶梯、4 像素条纹、像素棋盘 | 无 |
| 5 | `edge` | 6 条黑白硬边，区分推送接缝与面板串扰 | 无 |
| 6 | `text` | 文本渲染与 4 像素对齐的居中计算 | 无 |
| 7 | `scroll` | 每帧整屏重绘，用于评估带宽与流畅度 | 无 |
| 8 | `backlight` | 背光 5%–100% 往复 | 无 |
| 9 | `touch` | 触点位置与坐标，40 像素网格为参照 | 手指 |
| 10 | `rgb` | 红绿蓝白依次循环，屏上有同分量色块 | 无 |
| 11 | `audio` | 播放 C 大调音阶 | 喇叭 |
| 12 | `status` | 电池电压与 MicroSD 挂载情况 | 无 |

9 至 12 号场景随对应子系统开关参与编译：子系统关闭时，场景不存在。

场景通过 `enter` / `exit` 钩子管理硬件状态，离开时还原。例如 `rgb` 在退出时熄灭
灯珠，`backlight` 在退出时恢复满亮度，`audio` 在退出时静音。否则残留状态会一直
生效并干扰后续场景的判读。

## 六、可选子系统

`components/bsp/Kconfig.projbuild` 中五个开关，默认全部关闭：

| 开关 | 子系统 | 关闭时 |
| --- | --- | --- |
| `BSP_ENABLE_TOUCH` | 触摸 | 不编译驱动与 `touch` 场景 |
| `BSP_ENABLE_RGB` | RGB 指示灯 | 不编译驱动与 `rgb` 场景 |
| `BSP_ENABLE_AUDIO` | 音频 | 不编译驱动与 `audio` 场景 |
| `BSP_ENABLE_BATTERY` | 电池检测 | 不编译驱动与 `status` 场景的电压部分 |
| `BSP_ENABLE_SDCARD` | MicroSD | 不编译驱动与 `status` 场景的存储部分 |

### 必需子系统与可选子系统的失败策略

| 类别 | 成员 | 失败后果 |
| --- | --- | --- |
| 必需 | 显示、背光、按键、I2C 总线 | 初始化失败即中止启动 |
| 可选 | 触摸、RGB、音频、电池、MicroSD | 仅告警降级，其余功能照常 |

可选子系统在硬件上可以不存在：未插卡、未接喇叭、编解码器未焊接。这些情况不应
导致整机无法启动，因此它们的初始化失败只降级对应功能。

### I2C 总线归属

触摸控制器与音频编解码共用 IO38/IO39 一条总线，总线由 `bsp_i2c` 唯一持有。
其它模块不得自行创建总线：同一组引脚重复创建会失败。
`esp_driver_i2c` 的 master 驱动线程安全，多任务并发访问无需额外加锁。

## 七、宿主侧测试

不需要硬件，也不需要 ESP-IDF 环境：

```bash
scripts/host-tests.sh
```

两部分：

1. **`gfx` 单元测试** —— 字形渲染、画布裁剪、跨越式画布写入的边界条件。
2. **场景渲染校验** —— `tools/preview` 直接编译 `main/scenes/` 中与硬件无关的
   8 个场景源码，在宿主机上渲染整屏并检查：

   | 检查 | 适用范围 |
   | --- | --- |
   | 整屏覆盖（无未写入像素） | 全部 8 个场景 |
   | 逐像素断言布局不变量（彩带边界、灰阶阶梯、条纹相位、棋盘反相） | `pattern` |
   | 字符图输出 | 全部 8 个场景 |
   | 24 位 BMP 输出（`preview <场景> <输出.bmp>`） | 全部 8 个场景 |

   其余 7 个场景的数值判据目前只有整屏覆盖一项，颜色、元素位置与文字居中
   尚未由断言覆盖。场景源码在设备与宿主机上是同一份文件，不存在"测试用的副本"。

### 提交前门禁

```bash
scripts/check.sh
```

依次运行宿主侧测试与三套配置构建，任一项失败即非零退出。

门禁是**唯一**的自动检查入口。本工程不使用 CI。

## 十、已知限制

- 面板对强对比水平边缘存在轻微串扰，见场景 5 的判据。这是面板特性，非驱动缺陷。
- QSPI 像素时钟设为 80 MHz。ST77922 数据手册 V1.2 规定写模式最小串行时钟周期
  `TSCYCW ≥ 16 ns`，对应上限 62.5 MHz，本工程超出该限值。厂商参考配置同样使用
  80 MHz。如需严格满足数据手册限值，下调 `BSP_LCD_PIXEL_CLOCK_HZ`。
- 尚无 MicroSD 实机验证，SDIO 四位接线与槽位选择未确认。
- 功放型号在厂商资料中不一致：用户手册写 FM8002E，原理图写 SC8002B，
  原理图全图无 FM8002E。本工程按 FM8002E 记述，未改变驱动行为
  （功放由 ES8311 驱动的使能引脚控制，与具体型号无关）。
